# ACP client feature inventory (spec + Zed)

- **Date read:** 2026-11-23
- **Spec:** `agentclientprotocol/agent-client-protocol` at commit `01a54c84f39508f73fab4d41362baf51e1320374` (2026-11-22). Stable schema **schema-v1.34.1** (2026-11-21), wire `protocolVersion: 1`. A v2 schema exists as **schema-v2.0.0-beta.3** (2026-11-21); it is noted only where it changes what a client must do.
  - Spec base: `S = https://github.com/agentclientprotocol/agent-client-protocol/blob/01a54c84f39508f73fab4d41362baf51e1320374`
  - Method registry: `S/schema/v1/meta.json` (stable) and `S/schema/v1/meta.unstable.json` (unstable)
- **Zed:** `zed-industries/zed` at commit `d31d1074a07b7bbaa43a52fef7847a00dd491baf` (2026-11-22). Zed depends on the `agent-client-protocol = "=5.4.0"` crate with features `unstable` and `unstable_protocol_v2` (repo `agentclientprotocol/rust-sdk`, tag `v5.4.0`).
  - Zed base: `Z = https://github.com/zed-industries/zed/blob/d31d1074a07b7bbaa43a52fef7847a00dd491baf/crates`
  - SDK base: `R = https://github.com/agentclientprotocol/rust-sdk/blob/v5.4.0/src/agent-client-protocol/src`
- **How this was read:** spec `.mdx` pages and schema JSON, plus Zed and SDK source files fetched with `gh api` at those commits. Line numbers refer to those commits. I ran nothing and observed no runtime behavior. Every "Zed behavior" cell comes from reading code. **unverified** marks claims I could not confirm in the source.

Two notes on the current spec, since older adapters may predate both:
1. **`session/set_model` no longer exists.** The unstable session-model API was removed in 0.13.5 (2026-06-01, PR #1325). Models are now a `session/set_config_option` option with `category: "model"`. Zed has no `set_model` code path.
2. **v1 stable now includes** `session/list`, `session/delete`, `session/resume`, `session/close`, `logout`, `elicitation/*`, `$/cancel_request`, `usage_update`, `notice`, `compaction_*`, `plan_update`/`plan_removed`, and subagents (`subagent_update`, `session_message*`). The newer items are gated behind client or agent capabilities.

## 2. Session lifecycle

| Item | Spec status (v1) | Zed behavior | Source |
|---|---|---|---|
| `session/new` | **Required.** Params `cwd` (absolute), `mcpServers` (required array, may be empty), optional `additionalDirectories` and `systemPrompt` (both capability-gated). The result has `sessionId` and optional `modes`/`configOptions`. | Sends the first work dir as `cwd`, other roots only if supported, and the project's MCP servers. With `acp-beta` + `options` it also sends initial config option values. After the response it applies the user's `default_mode` through `session/set_mode` and default config options through `session/set_config_option`, rolling back on error. If the caller abandoned the request and the agent supports close, it sends `session/close` for the orphaned session. | Spec `S/docs/protocol/v1/session-setup.mdx` L47-83. | `session/close` | Stable v1, gated by `sessionCapabilities.close`. The agent cancels ongoing work, then frees it. Idempotent. | `session/list`, `session/delete` | Stable v1, gated by `sessionCapabilities.list` / `.delete`. | Powers the thread-history list (`cwd` filter, cursor paging). `session_info_update` refreshes entries. | Unstable session methods: `session/fork`, `archive`, `unarchive`, `status`, `options`, `set_title`, `providers/*`, `mcp/message` | Unstable only (`meta.unstable.json`). | Only `session/options` usage was found, behind `acp-beta`. The rest were not checked (**unverified**). | `S/schema/v1/meta.unstable.json`. |
| `session/cancel` | **Required** notification. The client SHOULD mark non-finished tool calls `cancelled` right away and **MUST answer every pending `session/request_permission` with `{outcome:"cancelled"}`**. The agent MUST end the turn with `stopReason:"cancelled"`. The client SHOULD still accept updates after cancel. | Sends `session/cancel` while a turn is running. Marks Pending/WaitingForConfirmation/InProgress tool calls `Canceled`, resolves their permission requests with `Cancelled` (sent on the wire as `outcome: cancelled`), cancels open elicitations, sets the thread idle, and waits for the prompt task. A follow-up prompt typed during a permission wait also maps to `cancelled`. Gemini quirk: an `InternalError` whose details say "aborted" after cancel is turned into `StopReason::Cancelled`. | Spec `S/docs/protocol/v1/prompt-turn.mdx` L632-665. Zed `Z/acp_thread/src/acp_thread.rs#L7823-L7936`, `#L8059-L8095`. `v1.rs#L1773-L1782`, `#L1728-L1768`, `#L10245-L10259`. |
| `$/cancel_request` | Stable v1, optional to honor. When honored, the receiver answers the original request with a valid cancelled result or `-32800`. | SDK-level support. | Process spawn | Transport: stdio, newline-delimited JSON-RPC (`S/docs/protocol/v1/transports.mdx`). | Runs through the system shell non-interactively with literal args, the agent's env, and the first project root as cwd for local projects. | Process exit / crash | Not specified. | A watcher on child exit drains stdout/stderr (250 ms timeout), then emits `LoadError::Exited{status, trailing stderr}` to **every** session on that connection. **No automatic restart.** The UI shows "Server exited with status ..." plus stderr and a **Retry** button. Retry drops the cached connection, spawns a fresh process, and reopens the thread (load/resume). Dropping the owner kills the child (`OwnedChild::drop`), and app quit shuts down all connections. | Zed `Z/agent_servers/src/acp/runtime.rs#L132-L190`, `v1.rs#L674-L685`, `#L1290-L1306`. `transport.rs#L18-L24`. `conversation_view.rs#L1262-L1268`, `#L3437-L3455`. `agent_connection_store.rs#L96-L125`, `#L170-L184`. |

| `sessionUpdate` | Spec status | Zed behavior |
|---|---|---|
| `agent_message_chunk` | Stable. Optional `messageId`: the same ID is the same message. | Appended to an assistant message, grouped by `messageId`. |
| `agent_thought_chunk` | Stable. | Same, flagged as a thought (rendered as collapsible thinking). |
| `user_message_chunk` | Stable (replay, or echo). | Added as user content unless it echoes the optimistic message. |
| `tool_call` | Stable. Required: `toolCallId`, `title`. Optional: `kind`, `status` (default `pending`), `content`, `locations`, `rawInput`, `rawOutput`, `name`. | Upsert: an existing ID is patched. Legacy `_meta.terminal_info{terminal_id,cwd}` creates a display-only terminal. |

## What a minimal client needs to match Zed's v1 behavior

These are inferences from the tables above, not spec text.

- **Hard spec MUSTs on the client side:** send `initialize` first. Never call capability-gated methods without the capability (`session/load`, `resume`, `close`, `list`, `delete`, `logout`, http/sse MCP, `additionalDirectories`, `systemPrompt`). Keep prompt content within `promptCapabilities`. Answer every pending `session/request_permission` with `cancelled` when sending `session/cancel`. Answer every agent request (`-32601` for unknown ones). Implement every `fs/*` or `terminal/*` method you advertise.
- **Behaviors that are easy to miss:** `session/update` can arrive before the `session/new`/`load` response, so buffer by `sessionId`. `session/load` replays history before its response. A `tool_call_update` can reference an unseen ID. `content` replaces the whole array. When the response carries `configOptions`, ignore `modes`. Treat `-32002` on `session/close` as success. A crash affects every session on that process.
